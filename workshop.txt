title=APOCALIPSE [BR] - Vehicle Claim System
description=ApocalipseClaimSystem - Vehicle Claim System
description=
description=Server-authoritative vehicle ownership for Project Zomboid Build 42 multiplayer servers.
description=
description=Players can claim vehicles from the vehicle context/mechanics UI, release their own vehicles, manage allowed players, see their claimed cars from anywhere, and contest abandoned claims when the server threshold allows it. Claims are bound to the owner's SteamID and every critical action is validated by the server.
description=
description=Build Compatibility:
description=Tested and compatible with: Builds 42.13.1, 42.14, 42.15, 42.16, 42.17, 42.18, 42.19, 42.20
description=
description=Build 42.20 Vehicle Database Refactor:
description=42.20 adds a refactored server-side vehicle database export designed for dedicated-server integrations. The in-game source of truth remains Project Zomboid GlobalModData and vehicle ModData, but the mod now maintains a throttled filesystem projection that external services can read safely.
description=
description=Export location on the dedicated server:
description={Zomboid}/Lua/VehicleClaimSystemDatabase/
description=
description=Files written by the exporter:
description=- index.json: compact list of currently claimed vehicles, indexed by vehicleHash
description=- cars/<vehicleHash>.json: per-car snapshot with owner SteamID/name, vehicle name, script name, map coordinates, lastUpdated timestamp, and loaded vehicle container loot
description=- deleted/<vehicleHash>.json: tombstone files for released, contested, remotely released, or admin-cleared claims
description=
description=How to use it with external services:
description=- Backup services can watch/copy the VehicleClaimSystemDatabase folder and store the index plus per-car JSON snapshots outside the game server.
description=- Web panels or Discord/admin bots can read index.json for the claimed-car list, then load each cars/<vehicleHash>.json file for details.
description=- Frontend map tools can plot x/y coordinates and show owner, vehicle type, last update time, and the latest captured loot snapshot.
description=- Sync workers should treat the JSON files as read-only output from the game server. Do not write claim changes directly into these files; claims should still be changed through the mod/game server.
description=- Loot snapshots are refreshed when a claimed vehicle is loaded by the server, so unloaded cars may keep the last known inventory until they stream in again.
description=
description=This makes it much easier to mirror cars and their stored loot into external backup systems, web dashboards, audit tools, or player-facing vehicle viewers without scanning the live world from outside Project Zomboid.
